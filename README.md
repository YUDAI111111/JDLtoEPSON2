JDL to Epson 仕訳データ変換システム 詳細仕様書

1. システム概要

本システムは、JDL形式の仕訳データをEpson財務会計形式に変換・出力するための、Google Apps Script (GAS) ベースのデータ変換エンジンです。会計ソフト間における「勘定科目体系の構造的相違」をプログラムによって自動的に吸収し、手動による移行工数とヒューマンエラーを大幅に削減します。

3. 開発背景と設計思想

2.1. ソフト間の構造的相違の解消（銀行特例処理）
JDLとEpsonでは銀行口座の管理構造が根本的に異なるため、単純な置換では対応できません。本システムではこの差異を埋めるための専用ロジックを実装しています。
JDLの構造: 「普通預金」という勘定科目の下に、補助科目として「銀行名」を紐付ける親子構造です。
Epsonの構造: 「〇〇銀行」という銀行名自体が、独立した勘定科目として最上位に存在します。
解決策: 変換時にJDLの補助科目名をスキャンし、特定の銀行名が検出された場合にのみ、Epson側の独立した科目コードへ強制的に振り替える「オーバーライドロジック」を構築しました。

2.2. マスターデータの最適化
変換の精度を担保するため、参照元となるEpsonマスターデータ（科目・補助科目）は以下の手順で作成しています。
Epson側から出力した基準データをベースに、GASでの参照やスプレッドシート上での視認性を高めるための加工を施した上でインポートしています。
このマスターを基に、マッピング時のプルダウン生成や、コード・名称の相互補完（欠落情報の補完）を行っています。

3. 主要機能と実装アルゴリズム
   
3.1. 3段階のマッピング判定ロジック
JDL科目とEpson科目の親和性を以下の3段階で判定し、ユーザーの確認作業を効率化します。
完全一致: 名称が100%一致する場合。自動で紐付けを完了します。
部分一致（LCSアルゴリズム）: LCS（最長共通部分列）アルゴリズムを実装し、2文字以上の連続一致を検出。類似度スコアに基づき、候補を黄色くハイライトして提示します。
不一致: 一致する要素がない場合、赤色で警告し、手動選択を促します。

3.2. 学習型変換エンジン
一度確定させたマッピング情報は Mapping_store シートに永続化されます。
再利用性: 次回以降の変換では、過去の履歴から優先的にマッピングを行います。
連鎖補完: コードのみ、あるいは名称のみの情報であっても、マスターデータから不足分を逆引きして自動補完し、出力データの不備を防ぎます。

3.3. ユーザーインターフェース (UI/UX)
動的バリデーション: onEdit トリガーを活用。マッピングシートで親科目を選択した際、その科目に紐付く補助科目のみをプルダウンに表示させる動的制御を実装しています。
進捗の可視化: HTMLサイドバーにより、処理件数や推定残り時間をリアルタイムに表示し、大量データ処理時のユーザーの不安を解消します。

4. 入出力・技術仕様
入力データ: JDL仕訳データ（CSVからインポートしたスプレッドシート）。
出力形式: Epson財務会計公式ヘッダ（44項目）に準拠したCSV形式。
エンコード: 会計ソフトのインポート仕様に合わせ、Shift_JIS および CRLF（改行コード）で出力。
エラーハンドリング: 税区分が未知の場合やマッピングが未完了な行がある場合、不完全なデータ出力を防ぐために処理を中断するガードロジックを搭載。
